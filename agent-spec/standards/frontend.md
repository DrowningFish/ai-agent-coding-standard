# Vue 3 / React 前端规范

本规范适用于项目已确认选择Vue或React的情况。项目可在project-rules明确其他前端技术及其规范，既有稳定栈优先，不为模板默认选择重写工程。

## 框架选择

- 新项目必须选择 Vue 3 或 React 作为唯一主框架，并在确认后写入 `docs/architecture.md`。
- 选定后不得在同一应用中混用两个框架。
- 已有项目沿用现有框架、构建工具、包管理器、UI 库和目录结构。
- 默认使用 TypeScript；只有项目明确要求时才使用纯 JavaScript。
- UI 库跟随项目已有选择。新项目可以选用一套成熟组件库，但同一应用只使用一套 UI 和样式体系。

## 通用原则

- 组件保持单一职责；可复用逻辑提取为 composable、hook 或独立服务。
- 页面负责组合，不把请求、状态转换和复杂业务规则全部写进视图组件。
- 服务端数据、全局客户端状态和局部 UI 状态分开管理，不把所有状态放入全局仓库。
- API 调用通过统一入口处理基础地址、认证、超时、错误和数据转换。
- 路由、菜单和权限判断集中管理，不把同一规则复制到多个页面。
- 用户输入在界面提供及时反馈，但权限和业务校验仍由后端执行。
- 明确加载、空数据、失败、无权限和提交中状态，避免静默失败。
- 提交期间防止重复操作，重复请求的业务处理仍由服务端保证。
- 多次请求可能乱序返回时，避免旧结果覆盖新状态；组件卸载或离开页面时清理监听、定时器和相关请求，明确取消与失败后的状态恢复。

## 异步请求与范围切换

- 切换查询范围、关闭明细、重新打开同一对象及离开页面时，使旧请求失效。取消请求或使用序号、标识判断均可，沿用现有方案，不为此默认引入依赖。
- 旧请求的成功、错误和结束处理都不能覆盖当前数据、错误或加载状态。新请求失败时不能把旧范围记录和总数当作当前结果；需要保留缓存时明确展示其归属与过期状态。
- 组件卸载后不得继续更新页面；异步初始化返回后也不能继续发起已失效页面的后续请求。共享 composable 或 hook 的变更核查其他调用方，保持原分页、轮询和后台刷新契约。

## Vue 3

- 使用 Composition API 和 `<script setup>`。
- 组合式函数以 `use` 开头，负责一类可复用行为。
- Props 和 Emits 使用明确 TypeScript 类型；不得直接修改 Props。
- Pinia 只存放真正跨页面或跨组件共享的状态。

## React

- 使用函数组件和 Hooks。
- Hook 只在顶层调用，依赖数组必须真实反映依赖关系。
- 优先组合而非复杂继承或巨型上下文。
- 全局状态库只在组件状态和服务端数据工具无法合理解决时引入。

## 样式与可访问性

- 遵循项目既有样式方案，不同时引入多套组件库或 CSS 体系。
- 表单控件有标签，交互元素可通过键盘使用，状态不能只靠颜色表达。
- 响应式布局和目标浏览器范围在项目文档中明确。

## 测试与验证

- 对关键业务交互使用组件测试，对纯逻辑使用单元测试。
- 核心用户流程可使用少量端到端测试，不用端到端测试替代所有低层测试。
- 测试用户可观察行为，避免绑定组件内部实现。
- 涉及异步查询时按风险覆盖迟到成功、迟到失败、加载状态、新范围失败、无效筛选、关闭重开和卸载。使用可控制完成顺序的响应验证竞态，不依赖固定延时碰运气。
- 抽取源码逻辑或模拟框架能力时注明覆盖边界；替换 watch、生命周期或定时器的测试不能证明真实调度、分页触发或轮询正确。涉及这些行为时优先使用现有组件测试或浏览器验证，不强制所有项目引入新工具。

从 `package.json`、锁文件和 CI 确定包管理器及真实脚本，按改动选择类型检查、lint、相关测试、构建或浏览器交互检查，并完成仓库要求的检查。未定义的脚本不视为已有命令。

测试用户可观察结果；缺陷修复优先增加能复现问题的回归测试。构建通过不代表交互、可访问性或目标浏览器兼容性已验证。执行结果与未覆盖范围分开记录。
