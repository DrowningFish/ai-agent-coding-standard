# 产物交付约定

只在项目已要求增量包、安装包或其他产物时使用；不要求所有任务打包。通用约定不替换项目已有有效的发布方式。

先判断当前任务类型及产物要求的适用范围。代码迭代要求打包不意味着讨论、方案编写和单份文档也要打包；明确的文档交付或规则同步产物要求按实际执行。生成方案不授权实施、提交或部署方案。

## 交付前确认事实

- 从项目约定、现有脚本和交付记录确定产物类型、输出目录、编号、包含范围及使用方式，不把旧包或旧脚本的固定基准当作当前事实。
- 明确本次改动与接收环境的基准版本。源码提交基准和测试环境已安装的版本分别记录；不能只凭最大 ZIP 编号认定测试环境已安装它。
- 项目已授权每次迭代生成产物时直接执行，不重复询问；基准、目标或必要取舍缺失且会导致错误交付时提出具体问题。
- 区分源码增量、构建产物和依赖包。离线环境覆盖源码后仍需具备依赖；本机构建通过不证明对方离线构建或部署成功。

## 范围与生成

- 优先复用有效脚本并先核对它的输入、基准和输出。历史专项脚本可能只适用于某一次改动，不直接运行固定清单或固定测试结论。
- 明确列出本次文件与变更来源，不能把所有未提交文件都视为本次修改。项目要求提交后打包时从对应提交生成；无法确认提交或基准时不伪造，报告具体限制。
- 同一文件包含其他已有改动时，审查文件内差异及前序依赖。不能仅凭路径在清单内就将全部内容视为本次新增；不可分离且会实质影响交付范围时先确认，包中说明真实来源。
- 使用项目编号规则，不覆盖已有产物。包内保持约定目录结构，不包含无关文件、用户业务文件、凭据、日志和临时数据；源码增量通常排除构建目录和依赖，项目另有授权时按实际范围处理。
- 新增、修改、删除、重命名分别说明。文件覆盖 ZIP 不能表达删除时提供明确操作清单，不生成含糊的批量清理命令。
- SQL 和配置变化说明兼容性、迁移次序、依赖及验证方法；不得改写已发布迁移，不能默认删除对方数据。

## 校验与说明

- 生成后重新打开产物，核对条目与批准范围、文件内容或逐文件哈希；检查压缩包完整性，计算最终产物 SHA-256。
- 清单与包内条目对应，逐文件核对内容、大小和哈希；校验后若继续修改入包文件，应按编号约定重新生成并校验，最终报告最终包而非先前结果。已有对外交付包不覆盖。
- 使用项目既有清单格式，至少记录产物编号、基准、文件路径及 SHA-256；提交可用时附提交信息，未验证的基准明确标识。
- 使用说明包含适用版本、前置依赖、覆盖或安装步骤、删除清单、数据库变化、配置变化、真实测试结果及未覆盖范围。
- 恢复说明按实际变化编写。仅替换代码的回退不能宣称能逆转已经执行的数据库迁移；没有可验证恢复方案时如实写明。
- 交付报告包含准确路径、范围、基准、SHA-256、是否生成或校验成功、数据库影响及未完成项。
- 上述“说明/报告”是信息要求，默认在回复及原需求文档的交付位置简记，包内清单/安装说明按项目要求提供；不每个包另建项目交付文档，也不复制全套需求、设计和测试流水。打包及校验不自动触发全量业务回归，选测范围按workflow确定。

## 完成边界

代码验证、产物生成、产物校验、目标环境部署、目标环境验收分别记录。生成增量包不代表已部署；本地测试通过不代表另一测试环境已通过。打包不隐含远程部署授权。
